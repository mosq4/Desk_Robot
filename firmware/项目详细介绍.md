## 1. 项目概述

本项目是**绘画机器人系统的 ESP32C3 上位机固件**，承担 WiFi 接入点（AP）、Web 控制台、G-code 缓存与流式下发、以及与下位机 STM32 的板间通信职责。

整个绘画机器人采用 **双 MCU 架构**：

| 模块 | 主控芯片 | 核心职责 |
|------|----------|----------|
| 上位机（本项目）| ESP32C3 | WiFi AP、Web UI、HTTP API、G-code 缓存、协议桥接 |
| 下位机 | STM32 | 电机 FOC 驱动、运动学逆解/正解、G-code 队列执行、状态上报 |

**典型使用场景**：
1. 用户手机/电脑连接 ESP32 发出的 WiFi 热点 `DrawingRobot`
2. 浏览器访问 `http://192.168.4.1` 打开控制台网页
3. 在网页上用手指/鼠标手绘图案，或上传 G-code
4. 通过方向键将笔尖对准 A4 纸正中心，点击"设置零点"标定坐标系
5. 点击"开始绘画"，机器人自动按手绘轨迹落笔作画

### 4.2 protocol.h - 板间通信协议定义

**文件路径**：[src/protocol.h](file:///d:/实习/工程源码/drawing_robot_ESP32C3/src/protocol.h)

定义了 ESP32 与 STM32 之间通信的全部"契约"，**必须与 STM32 端保持二进制兼容**：

#### 4.2.1 核心数据结构

**`ProtoFrame_t` - 协议帧结构**
```c
typedef struct {
  uint8_t  cmd;                           // 命令码
  uint8_t  payload[PROTO_MAX_PAYLOAD];    // 负载数据（最大128字节）
  uint16_t len;                           // 负载实际长度
} ProtoFrame_t;
```

**`MotorInfo_t` - 单电机运行信息**
| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| pos | float | rad | 当前机械位置 |
| vel | float | rad/s | 当前角速度 |
| torque | float | N·m | 当前输出扭矩 |
| err | uint8_t | - | 状态码：0失能 1使能 8~E故障 FF无反馈 |
| t_mos | uint8_t | ℃ | 驱动器 MOS 管温度 |
| t_rotor | uint8_t | ℃ | 电机线圈温度 |

**`RobotStatus_t` - 机器人完整状态（44 字节上报）**
| 字段 | 类型 | 说明 |
|------|------|------|
| state | uint8_t | 状态机编号（STATE_*）|
| busy | uint8_t | 过渡态标记（回零/标定中=1）|
| pen | uint8_t | 笔状态：0抬笔 1落笔 |
| m1, m2 | MotorInfo_t | 双电机信息 |
| x, y | float | 正解末端位置（mm，相对零点）|
| queue_used | uint8_t | STM32 G-code 队列已用行数 |
| line_index | uint8_t | 当前执行行号 |
| fault | uint8_t | 故障码：0无 1逆解失败 2电机故障 |

### 4.3 protocol.cpp - 协议实现

**文件路径**：[src/protocol.cpp](file:///d:/实习/工程源码/drawing_robot_ESP32C3/src/protocol.cpp)

实现协议层的全部算法，核心函数说明：

| 函数 | 功能 | 实现要点 |
|------|------|----------|
| `protoCrc8()` | CRC8 校验计算 | poly=0x07, init=0x00，逐位模2除法 |
| `protoParseByte()` | 逐字节解析状态机 | 6 状态流转：HEAD→CMD→LEN_LO→LEN_HI→PAYLOAD→CRC |
| `protoSend()` | 组装帧并发送 | 自动计算 CRC8，一次性写入 Stream |
| `protoRecvFrame()` | 阻塞接收一帧 | 带超时（ms），循环喂入字节给状态机 |
| `protoParseStatus()` | 解析 44B 状态帧 | 按偏移表读取 float32/uint8 字段 |
| `protoPutFloat()` / `protoGetFloat()` | float 序列化 | `memcpy` 小端拷贝（ESP32/STM32 均为小端）|
| `stateName()` | 状态码转字符串 | switch 映射，用于日志和 JSON |

**字节流状态机设计**：
- 逐字节处理，无阻塞
- 使用 `static` 变量保存上下文（同一时刻只能有一个解析流）
- 遇到 0xA5 才同步，CRC 错误静默丢弃，保证字节流错位后能自动恢复

### 4.4 main.cpp - 主程序入口

**文件路径**：[src/main.cpp](file:///d:/实习/工程源码/drawing_robot_ESP32C3/src/main.cpp)

核心入口，包含 `setup()` 和 `loop()` 两个 Arduino 标准函数。

#### 4.4.1 全局状态变量

**状态缓存区**：
- `g_status`：最近一次 STM32 上报的完整状态
- `g_statusValid`：是否已收到至少一次状态帧
- `g_lastStatusMs`：最后收到状态帧的时间戳

**G-code 下发状态机**：
| 变量 | 类型 | 说明 |
|------|------|------|
| `g_prog` | `std::vector<String>` | G-code 程序行缓存 |
| `g_feedIdx` | size_t | 已下发且 ACK_OK 的行数索引 |
| `g_feeding` | bool | 流式下发开关 |
| `g_endSent` | bool | GCODE_END 帧是否已发送 |
| `g_feedRetryMs` | uint32_t | ACK_QUEUE_FULL 后的重试时间戳 |

**单例 pending（在途命令）**：
```cpp
struct {
  uint8_t  cmd;        // 在途命令码
  bool     waiting;    // 是否在等待 ACK
  bool     blocking;   // true=HTTP同步等待, false=feeder异步
  uint32_t deadline;   // 非阻塞模式超时截止
  int      ackResult;  // 阻塞模式收到的结果
} g_pending;
```
> 设计：系统同时只允许一条命令"在途"，避免并发冲突。阻塞模式用于 HTTP 控制接口，非阻塞用于 feeder 流式下发。

#### 4.4.2 setup() - 初始化流程

```
1. USB CDC 调试串口 (115200)
   ↓
2. UART1 初始化 (115200-8N1, RX=6, TX=7)
   ↓
3. WiFi 切换到 AP 模式
   ↓
4. softAP 启动 SSID=DrawingRobot, PASS=12345678
   ↓
5. 打印 AP IP (默认 192.168.4.1)
   ↓
6. 注册 5 个 HTTP 路由
   ↓
7. Web 服务器开始监听 80 端口
```

#### 4.4.3 loop() - 主循环调度

每轮循环顺序执行三件事，单次耗时约 2~3ms：
```cpp
void loop() {
  server.handleClient();      // 1. 处理 HTTP 请求（非阻塞）
  stm32ProcessFrames(2);      // 2. 接收 STM32 串口帧（最多2ms）
  feederTick();               // 3. G-code 流式下发调度（非阻塞）
}
```

#### 4.4.4 HTTP 路由处理函数

| 处理函数 | 路由 | 说明 |
|---------|------|------|
| `handleRoot()` | `GET /` | 从 PROGMEM 发送网页 HTML |
| `handleStatus()` | `GET /api/status` | snprintf 组装完整状态 JSON |
| `handleConfig()` | `GET /api/config` | 下发 config.h 中集中参数 |
| `handleCtl()` | `POST /api/ctl` | 控制命令分发（start/jogx/stop/等）|
| `handleGcode()` | `POST /api/gcode` | 按行拆分 G-code 文本存入 g_prog |

#### 4.4.5 下发调度核心函数

**`stm32ProcessFrames(maxMs)`**：
- 在 maxMs 时间窗口内循环读串口
- 分发两种帧：`CMD_STATUS` 更新状态缓存，`CMD_ACK` 根据 blocking 模式更新 pending/feeder

**`sendCtlWaitAck(cmd, payload, len, timeoutMs)`**：
- 阻塞式发送（供 HTTP 控制接口）
- 先等 feeder 在途结束（最多 200ms），设为 blocking 模式，发送后轮询等待 ACK

**`feederTick()`**：
- 非阻塞流式下发调度器，在 loop 中每轮调用
- 状态流转：`等待 → 发LINE → 等ACK → (OK推进 / QUEUE_FULL 60ms退避 / ERROR终止)`
- 全部行发完后发送 `GCODE_END` 标志帧

## 5. ESP32 <-> STM32 板间通信协议

### 5.1 帧格式

```
字节偏移:  [0]      [1]    [2]    [3]     [4...4+LEN-1]   [4+LEN]
内容:     0xA5    CMD   LEN_LO LEN_HI    payload...       CRC8
          帧头   命令码   长度（16位小端）    变长负载     校验和
```

**总长度** = 5 + LEN 字节

**CRC 计算范围**：CMD + LEN（2字节）+ payload，共 3 + LEN 字节
**CRC 算法**：CRC8，多项式 `0x07`，初始值 `0x00`

### 5.2 命令码定义

| 方向 | 命令码 | 宏名 | payload | 说明 |
|------|--------|------|---------|------|
| ESP→STM | 0x01 | `CMD_GCODE_LINE` | ASCII 字符串 | 单行 G-code |
| ESP→STM | 0x02 | `CMD_START_DRAW` | 无 | 开始绘画 |
| ESP→STM | 0x03 | `CMD_SET_ZERO` | 无 | 标定零点 |
| ESP→STM | 0x04 | `CMD_STOP_DRAW` | 无 | 停止绘画 |
| ESP→STM | 0x05 | `CMD_PAUSE_DRAW` | 无 | 暂停 |
| ESP→STM | 0x06 | `CMD_RESUME_DRAW` | 无 | 继续 |
| ESP→STM | 0x07 | `CMD_RETURN_ZERO` | 无 | 回零 |
| ESP→STM | 0x08 | `CMD_ESTOP` | 无 | 急停 |
| ESP→STM | 0x09 | `CMD_JOG_X` | float32 (4B) | 末端X速度 mm/s |
| ESP→STM | 0x0A | `CMD_JOG_Y` | float32 (4B) | 末端Y速度 mm/s |
| ESP→STM | 0x0B | `CMD_JOG_MOTOR` | u8+float32 | 单电机点动（调试）|
| ESP→STM | 0x0C | `CMD_GET_STATUS` | 无 | 主动查询状态 |
| ESP→STM | 0x0D | `CMD_SET_PEN` | u8 | 直接抬落笔 |
| ESP→STM | 0x0E | `CMD_CLEAR_ESTOP` | 无 | 解除急停 |
| ESP→STM | 0x0F | `CMD_GCODE_END` | 无 | G-code 流结束标志 |
| STM→ESP | 0x80 | `CMD_ACK` | [u8 cmd, u8 code] | 应答确认 |
| STM→ESP | 0x81 | `CMD_STATUS` | 44 字节二进制 | 机器人实时状态 |

### 5.3 ACK 结果码

| 值 | 宏名 | 含义 |
|----|------|------|
| 0 | `ACK_OK` | 成功 / 已入队 |
| 1 | `ACK_QUEUE_FULL` | G-code 队列已满（ESP32 需稍后重发）|
| 2 | `ACK_BAD_STATE` | 当前状态不允许该命令 |
| 3 | `ACK_ERROR` | 其他错误（拒绝执行）|

### 6.5 POST /api/gcode - G-code 上传

**请求**：Content-Type 为文本（非 JSON），每行一条 G-code，`\n` 分隔。
示例 body：
```
G0 X-40.00 Y20.00 F1500
G1 X-20.00 Y20.00 F1500
G1 X-20.00 Y50.00 F1500
```

**响应示例**：
```json
{"ok": 1, "lines": 3, "msg": "已缓存, 点击开始绘画后自动下发"}
```

**规则**：
- 单次最大 **400 行**（`MAX_PROG_LINES`），超出返回 ok=0
- 仅缓存，不立即下发
- RUNNING / PAUSED 状态下上传被拒绝
- ESP32 缓存，STM32 队列仅 16 行，之后边执行边 ACK 流控下发

### 6.6 POST /api/ctl - 控制命令

**请求**：body 为纯文本命令（非 JSON）

**响应 JSON**：
```json
{"ok": 1, "code": 0, "msg": "ok"}
```

| code | 含义 |
|------|------|
| 0 | 成功 |
| 1 | STM32 无响应（超时）|
| 2 | 当前状态不允许 |
| 3 | STM32 拒绝 |
| 4 | 未知命令 |
| 5 | start 时 G-code 未缓存 |

**支持的命令列表**：

| 命令文本 | 对应帧 | 说明 |
|---------|--------|------|
| `start` | GCODE_LINE + START_DRAW | 先下发首行确保队列非空，再启动 |
| `stop` | STOP_DRAW | 停止并清空 ESP32 缓存 |
| `pause` | PAUSE_DRAW | 暂停 |
| `resume` | RESUME_DRAW | 继续 |
| `estop` | ESTOP | 急停，清空缓存，禁止点动 |
| `clear_estop` | CLEAR_ESTOP | 解除急停，重新使能电机 |
| `setzero` | SET_ZERO | 标定当前笔尖位置为零点 |
| `return_zero` | RETURN_ZERO | 抬笔回零点（READY/JOG 态可用）|
| `jogx <v>` | JOG_X(float) | X 轴速度（mm/s），0 停止 |
| `jogy <v>` | JOG_Y(float) | Y 轴速度（mm/s），0 停止 |

## 7. 网页控制台功能详解

### 7.1 界面布局

```
┌─────────────────────────────────────────────────────────┐
│                   绘画机器人控制台（H1）                   │
├──────────────────────────────────┬──────────────────────┤
│                                  │  ┌────────────────┐  │
│                                  │  │    ▲           │  │

│                                  │  └────────────────┘  │
│    橙色：用户手绘笔迹             │  速度滑杆 5~30 mm/s  │
│    虚线：可绘画区边界（留边10mm）  │                      │
│    绿色十字：机器人实际位置        │  [开始][停止][暂停] │
│                                  │  [继续][急停][取消]  │
```

- 使用 CSS `flex-wrap: wrap` 自动适配窄屏（手机竖屏自动上下堆叠）
- `max-width:100%` 让画板在窄屏自动按比例缩小

### 7.2 手绘画板

**画布尺寸计算**：
```
宽度 = A4_W_MM × CANVAS_PX_PER_MM = 210 × 2 = 420 px
高度 = A4_H_MM × CANVAS_PX_PER_MM = 297 × 2 = 594 px
```

**输入技术栈**：统一使用 **Pointer Events** API
- 兼容鼠标（`mousedown`/`mousemove`/`mouseup`）
- 兼容触摸屏（`touchstart`/`touchmove`/`touchend`）
- 兼容触控笔 / 数位板
- `setPointerCapture` 保证指针滑出画布边界也能收到事件

**采样优化**：pointermove 时追加点的阈值为 **欧氏距离 > 3 像素**
- 防止鼠标/触摸抖动产生过密点
- 避免 1cm 曲线产生数千条 G-code 行导致行数爆炸

### 7.3 G-code 生成规则

每一笔独立处理：

```
笔画 [P0, P1, P2, ..., Pn]
    ↓
第1行：G0 X<P0.x> Y<P0.y> F1500    抬笔快速移动到起点
第2行：G1 X<P1.x> Y<P1.y> F1500    落笔直线到 P1
第3行：G1 X<P2.x> Y<P2.y> F1500    落笔直线到 P2
  ...
第n+1行：G1 X<Pn.x> Y<Pn.y> F1500  落笔直线到终点
```

- **G0**：快速移动（抬笔状态，STM32 内部先抬笔）
- **G1**：直线插补（落笔状态，STM32 先落笔再运动）
- **F 参数**：进给速度 mm/min（默认 1500 = 25 mm/s）

### 7.4 方向键点动控制

**交互模式**：按住移动，松开停止
- 使用 Pointer Events 的 `pointerdown` 触发开始
- `pointerup` / `pointercancel` 触发停止（含手指滑出按钮/来电中断等异常场景）

**看门狗安全机制**：
```
网页端：按住期间每 400ms 重发一次 jog 速度指令
STM32 端：点动速度 1s 看门狗超时自动清零停止
```
→ 即使浏览器崩溃、断网、手机锁屏，机器人也会在 1s 后自动停止，不会失控。

**速度滑杆**：范围 5~30 mm/s（步长 5mm/s），默认 10 mm/s
- 实际末端速度受 STM32 端 `JOG_SPEED_CAP` 二次限幅（3 cm/s 硬上限）

### 7.5 控制按钮

| 按钮 | 颜色语义 | 可用性限制 |
|------|---------|-----------|
| 生成Gcode | 蓝色 primary | 始终可用 |
| 开始绘画 | 蓝色 primary | 需已缓存 G-code |
| 停止绘画 | 中性灰 | 运行中可用 |
| 暂停 / 继续 | 中性灰 | 对应状态可用 |
| 急停 | 红色 danger | 任何状态可用（最高优先级）|
| 取消急停 | 橙色 warn | 仅 EMERGENCY 态 |
| 回零 / 方向键 | 浅蓝/中性 | 仅 READY(1) / JOG(4) 态 |
| 设置零点 | 绿色 cal | 建议就绪态使用 |

### 7.6 状态实时展示

**200ms 轮询周期**：平衡实时性与 ESP32 CPU 负载

状态面板内容（从上到下）：
1. **状态徽章**：彩色圆角标签，RUNNING=绿色，READY=蓝色，PAUSED=黄色，EMERGENCY/ERROR=红色
2. **过渡态标记**：`(处理中)` 表示 HOMING/ZEROING 等过渡
3. **失联警告**：`[STM32无响应]` 红色提示（>1.5s 无状态帧）
4. **笔状态**：抬笔 / 落笔
5. **故障码**：0无 / F1逆解失败 / F2电机故障
6. **电机详情** × 2：位置(rad)、速度(rad/s)、扭矩(N·m)、状态码、MOS温度、线圈温度（e=255 显示 `--`）
7. **末端位置**：X / Y 坐标（mm，相对零点）
8. **STM32 进度**：队列已用行数 / 已执行行号
9. **下发进度**：`feedIdx / feedTotal`（正在下发）或 `N 行就绪`（待开始）

**绿色十字（末端位置可视化）**：
- 当末端 x/y 坐标在 `|x| ≤ A4_W/2, |y| ≤ A4_H/2` 范围内时在画板上显示
- 超出范围（可能正在回零或机械零位）不显示，避免误导

```
ESP32 上电
    │
    ▼
┌──────────────────┐

│ @115200          │
└────────┬─────────┘
         ▼
┌──────────────────┐
│ UART1 @115200    │ → 与 STM32 建立串口链路
└────────┬─────────┘
         ▼
┌──────────────────┐
│ WiFi.mode(AP)    │
│ softAP()         │ → SSID "DrawingRobot" 可见
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 注册5条路由      │ → server.on(...) × 5
│ server.begin(80) │ → 开始监听 HTTP 80 端口
└────────┬─────────┘
         ▼
┌──────────────────┐
│ loop() 循环       │
│  ├ handleClient() │ ← 用户浏览器访问
│  ├ stm32Process() │ ← STM32 周期上报状态
│  └ feederTick()   │   (g_feeding=false, 暂不工作)
└──────────────────┘
```

### 8.2 零点标定流程

零点是世界坐标系的原点（A4 纸中心），每次开机/断电后需要重新标定（零点不保存）。

```
用户操作: 连接WiFi → 打开页面 → 按方向键调整笔尖位置
           │
           ▼  绿色十字对齐纸面中心后
         点击 [设置零点]
           │
           ▼
    POST /api/ctl "setzero"
           │
           ▼
    sendCtlWaitAck(CMD_SET_ZERO)
           │
           ▼
        STM32 收到
           │
           ├ 状态: READY → ZEROING → READY（约 0.4s）
           └ 将当前(x,y)写入内部 zero_offset 变量
           │
           ▼
    ACK_OK 返回网页
    消息: "零点已标定到当前笔尖位置"
```

### 8.3 手绘绘画完整流程

```
步骤1: 手绘图案
  用户在画板上绘制多笔橙色笔迹
           │
步骤2: 生成 G-code
  点击 [生成Gcode]
           │
           ▼
  JS: strokes → G-code行数组
      每笔：G0起点 + G1后续点
           │
           ▼
  POST /api/gcode  (400行上限检查)
           │
           ▼
  ESP32: 存入 g_prog 向量
  响应: "已缓存 N 行 Gcode"
           │
步骤3: 开始绘画
  点击 [开始绘画]
           │
           ▼
  POST /api/ctl "start"
           │
           ▼
  feedOneLineBlocking()
    └─ sendCtlWaitAck(CMD_GCODE_LINE, 行0)  → STM32队列: [行0]
    └─ ACK_OK → g_feedIdx = 1
           │
  sendCtlWaitAck(CMD_START_DRAW)
    └─ STM32: 队列非空，状态 READY → RUNNING，开始执行行0
    └─ ACK_OK → g_feeding = true
           │
步骤4: 后台流式下发（feederTick 自动运转）
  ┌─────────────────────────────────────────────┐
  │ loop() 每轮调用 feederTick()                  │
  │   ├─ if (!waiting) → 发送 g_prog[feedIdx]    │
  │   ├─ 等 ACK_OK → feedIdx++                  │
  │   ├─ 等 ACK_QUEUE_FULL → 60ms 后重发         │
  │   └─ 全部发完 → 发 CMD_GCODE_END            │
  └─────────────────────────────────────────────┘
           │
步骤5: 绘画完成
  STM32 端：队列清空 + 已收到 GCODE_END → RUNNING → READY
  ESP32 端：g_feeding = false → 状态页显示 "就绪"
```

### 8.4 G-code 流式下发流程

```
feederTick() 调用（每轮 loop）
    │
    ├─ g_feeding == false? ──是──► return
    │
    ├─ g_pending.waiting == true?
    │       │
    │       ├─ 非阻塞模式 && 超时deadline到? ──是──► 清waiting, 记日志, 重发
    │       └─ 否则 ──► return (继续等待)
    │
    ├─ feedIdx >= g_prog.size?
    │       │
    │       └─ 是:
    │            ├─ g_endSent == false?
    │            │     └─ 发送 CMD_GCODE_END, 记 deadline, g_endSent=true
    │            └─ g_endSent == true?
    │                  └─ END ACK OK → g_feeding=false, 输出 "delivery complete"
    │
    ├─ millis() < g_feedRetryMs? ──是──► return (队列满退避中)
    │
    └─ 正常发送:
         设置 pending.cmd = CMD_GCODE_LINE
         设置 deadline = millis() + 600ms
         protoSend(g_prog[feedIdx])
```

## 9. 安全机制设计

### 9.1 点动看门狗

**场景**：方向键按住移动时手机突然锁屏 / 浏览器崩溃 / WiFi 断开

**机制**：
```
网页端: setInterval(() => jogSend(axis, speed), 400ms)
           ↓ 每 400ms 重发一次速度指令
STM32 端: 点动看门狗定时器 (1s 超时)
           ├─ 收到 jog 指令 → 清看门狗, 保持速度
           └─ 1s 内未收到新 jog 指令 → 速度强制清零, 停止运动
```
→ 最坏情况：失控 1s 后自动停止

### 9.2 急停机制

**触发方式**：
1. 网页点击红色"急停"按钮
2. STM32 硬件急停输入（如物理按钮）

**急停动作**：
- ESP32 端：`CMD_ESTOP` 帧下发 + 立即 `g_feeding=false` + 清空 `g_prog` 缓存
- STM32 端：状态 → EMERGENCY，立即切断电机 PWM 输出（禁止任何运动），清空队列

**恢复方式**：点击橙色"取消急停"→ `CMD_CLEAR_ESTOP` → 状态回到 READY，电机重新使能（零点保持，无需重新标定）

### 9.3 状态机校验

STM32 端每个命令都有状态白名单，非法状态下命令直接返回 `ACK_BAD_STATE`：

| 命令 | 允许状态 |
|------|---------|
| START_DRAW | READY |
| SET_ZERO | READY, JOG |
| STOP_DRAW | RUNNING, PAUSED |
| PAUSE_DRAW | RUNNING |
| RESUME_DRAW | PAUSED |
| RETURN_ZERO | READY, JOG |
| JOG_X/JOG_Y | READY, JOG |
| CLEAR_ESTOP | EMERGENCY |

网页端也做了对应限制（按钮 disabled），双重保险。

### 9.4 队列流控

STM32 G-code 队列容量仅 **16 行**，若一次性灌入 400 行会丢包溢出。

**ACK 流控策略**：
- ESP32 每次只发 1 行，收到 `ACK_OK` 后再发下一行
- 收到 `ACK_QUEUE_FULL`（队列满 16 行）：延迟 60ms 后重发同一行，给 STM32 时间消费队列
- 偶发串口丢包：600ms ACK 超时自动重发当前行

## 11. 参数配置说明

所有参数集中在 [src/config.h](file:///d:/实习/工程源码/drawing_robot_ESP32C3/src/config.h)，修改后重新编译烧录即可生效。

**常见修改场景**：

| 需求 | 修改什么 | 注意事项 |
|------|---------|---------|
| 修改 WiFi 密码 | `AP_PASS` | ≥ 8 字符，否则 softAP 可能失败 |
| 增加 G-code 行数上限 | `MAX_PROG_LINES` | ESP32 SRAM 有限，建议 ≤ 2000 |
| 增大画布像素（更精细）| `CANVAS_PX_PER_MM` | 从 2→3 会使画布变为 630×891px，手写采样点更多 |
| 调慢点动默认速度 | `JOG_SPEED_DEF_MM_S` | 不建议 < 5mm/s，会显得太慢 |
| 调慢绘画进给 | `DRAW_FEED_MM_MIN` | 换算：mm/min ÷ 60 = mm/s，建议 ≥ 600 |
| 换用不同纸张尺寸 | `A4_W_MM`, `A4_H_MM` | **必须同步修改 STM32 端 robot_config.h** |
| ACK 超时太频繁 | `ACK_TIMEOUT_MS` | 串口噪声大时从 600 → 1000 |
| STM32 失联告警太灵敏 | `STATUS_STALE_MS` | 状态上报变慢时适当增大 |

## 12. 调试与故障排查

### 12.1 调试串口输出

ESP32 USB 口连接 PC，打开串口监视器 115200 可看到调试日志：

| 日志前缀 | 含义 |
|---------|------|
| `[i]` | 信息（普通事件）|
| `[W]` | 警告（非致命，如 ACK timeout）|
| `[ERR]` | 错误（G-code 被拒绝等）|

**常见日志示例**：
```
[i] received 128 gcode lines, buffered (start to feed)   # G-code 上传成功
[W] ACK timeout, will resend line                        # 串口偶发丢包，自动重发
[ERR] G-code line 45 rejected, code=2                    # 第45行在错误状态下被拒
[i] G-code delivery complete                              # 全部下发完成
```

### 12.2 常见问题排查

#### Q1. WiFi 搜不到 DrawingRobot 热点？
- 排查：看串口日志是否有 `[ERR] softAP failed`
- 原因：`AP_PASS` < 8 字符 / ESP32 电源不足
- 解决：改密码到 8 位以上 / 用 5V 2A USB 供电

#### Q2. 打开网页一直显示"连接中..."或状态面板无更新？
- 排查：F12 → Network → 看 `/api/status` 是否一直 pending
- 原因 1：ESP32 和 STM32 接线错 / 未共地
- 原因 2：STM32 未上电或固件未运行
- 解决：检查接线，确保两端 GND 连接，STM32 串口在发状态帧

#### Q3. 点击"开始绘画"提示"STM32无响应"？
- 排查：ACK 超时（600ms 未收到 CMD_ACK）
- 原因 1：TX/RX 接反（TX 应对 RX，RX 对 TX）
- 原因 2：波特率不一致（两端都要是 115200-8N1）
- 原因 3：STM32 协议帧格式不匹配（protocol.h 版本不一致）

#### Q4. 绘画位置偏移，左下角跑到纸外面？
- 原因：未标定零点 / 零点标错位置 / 画布参数不一致
- 解决：
  1. 方向键把绿色十字对齐纸中心后再点"设置零点"
  2. 确认 ESP32 `config.h` 与 STM32 `robot_config.h` 的 A4 尺寸、留边一致

#### Q5. 方向键按住移动，但偶尔会"卡顿"停一下？
- 正常现象：400ms 周期重发，如果 WiFi 抖动导致重发包延迟到达，STM32 看门狗在 1s 边缘清零停止
- 解决：暂无（安全机制与响应速度的 trade-off），可考虑把网页端 400ms 改到 300ms

#### Q6. 绘画到一半突然停止，状态显示"急停"？
- 排查：状态面板故障码 F0? F1? F2?
  - F0（无故障但状态急停）：可能误触急停按钮 / STM32 硬件急停输入触发
  - F1 逆解失败：某行 G-code 坐标超出机械工作空间（如 X>105mm）
  - F2 电机故障：电机驱动器过温/过流/堵转，查看电机 MOS/线圈温度是否 > 80℃

#### Q7. G-code 生成后"超出最大行数"？
- 原因：`MAX_PROG_LINES` 默认 400，手绘曲线过长会超限
- 解决：
  1. 画板上减少笔画细节（手绘时大笔触不要太密）
  2. 或调大 `MAX_PROG_LINES`（注意内存占用，每行 ~40 字节 String）

## 14. 坐标系约定

### 世界坐标系（绘画坐标系）

```
                     纸面 (Y+, 上)
                    ▲
                    │
     (-105, 148.5) ┌┼─────────────────────┐ (+105, 148.5)
                   │┼                     │
                   │┼      A4 纸面        │
                   │┼   (210mm × 297mm)   │
    (-105, 0) ─────┼┼──────(0,0)──────────┼────── (+105, 0)  ← X+, 右
                   │┼      ↑零点          │
                   │┼   (纸中心标定)       │
                   │┼                     │
     (-105,-148.5) └┴─────────────────────┘ (+105,-148.5)
                    │
                    ▼
                   (Y-, 下)
```

**参数速算**：
- X 范围：±(A4_W_MM / 2 - DRAW_MARGIN_MM) = ±95 mm（可绘画区，含留边 10mm）
- Y 范围：±(A4_H_MM / 2 - DRAW_MARGIN_MM) = ±138.5 mm

### 画板像素坐标系 ↔ 世界坐标变换

```
画板像素 (0,0) ─────────────► X+ (420, 0)
    │
    │     变换公式：
    │       world.x = (pixel.x - width/2) / PX_PER_MM
    │       world.y = (height/2 - pixel.y) / PX_PER_MM
    │
    ▼
  Y+ (0, 594)

注意：像素坐标系 Y 轴向下，世界坐标 Y 轴向上 → 符号取反
```
